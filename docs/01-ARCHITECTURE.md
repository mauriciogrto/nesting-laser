# Architecture

## Sheet-area composition

The saved-order detail calculates per-sheet area inside compensated part contours, the intact rectangular remnant from the saved result, and the residual void/hole area. It shows these as separate percentages; the part-contour percentage is fixed for an unchanged lot and must not be presented as a packing improvement. The preview/editor retains its live contour-area figure while labeling it explicitly.

## Interface visual (2026-10-01)

The Blade application uses a shared DashStack-inspired dark shell: fixed sidebar on wide screens, a compact overlay menu on narrower screens, top action bar, and shared visual tokens in `resources/css/app.css`. The reference palette uses `#1b2431` for the workspace, `#273142` for panels/navigation and `#4880ff` for the primary action. Existing route names, permissions and page content remain in place. The arrangement canvas intentionally stays light to preserve cutting-path contrast. Shared guest and button components apply the same visual language to authentication and forms.

## Phase 0

Laravel application in `nesting-laser/`, using Blade views and session authentication.
MySQL stores users, sessions, cache and queued jobs. The database queue worker runs as a separate process.
Local tooling and database data belong in root `.local/`, excluded from version control.

## Phase 1 data model

`materiais` own `espessuras_material`; each `chapa` references one material and compatible thickness. The sheet form accepts only material, thickness, width and height; creation assigns one available new sheet and keeps origin, status, count and cost internal. Editing physical attributes does not overwrite inventory fields. `pecas` store a private DXF path and, later, extracted raw geometry; a blank piece name resolves from the uploaded DXF basename. `pedidos_corte` refer to a sheet and connect to pieces through `pedido_corte_pecas` with quantities. `movimentacoes_estoque` preserve stock history. PHP backed enums represent sheet origin/status, order status and movement type.

## Planned service boundaries

Python owns DXF geometry extraction, offsets and CNC output. Laravel invokes it using Symfony Process argument arrays.
Node exposes an HTTP nesting endpoint. Laravel jobs orchestrate geometry preparation and nesting.
Raw part geometry stays immutable; compensated geometry belongs to each order result.

On hosts where PHP-FPM disables `proc_open`, `ExecutorPython` can send whitelisted Python operations to a loopback Node service with a bearer token. The service launches Python with argument arrays and returns base64 output, including binary PDF bytes. Local/CLI execution retains Symfony Process. The loopback service validates script names and private storage paths; both nesting routes also require the token when configured.

The UNI5 test host sets `NESTING_PC_WORKER_ENABLED=true` because it does not retain a reliable Node process. `PcWorkerBridge` writes UUID-named JSON requests to private `storage/app/private/engine-bridge/requests`, waits for a response in the matching private directory, and checks a recent heartbeat before accepting work. `scripts/pc-worker.py` runs on the owner's Windows PC, opens an outbound SFTP connection with a pinned host key, polls requests, executes local Node/Python, and uploads responses and binary outputs. The Windows `NestLaserPcWorkerManual` task has **no triggers** and starts only when explicitly requested; the earlier login/minute-triggered task was removed on 2026-10-09. While that manual task is running, its launcher removes orphaned worker children and restarts a child that exits unexpectedly; `scripts/stop-pc-worker.ps1` stops the task, any orphaned children and the dedicated Node listener. The worker reconnects after SFTP errors, updates the heartbeat between queued tasks, ignores requests removed by Laravel, and purges temporary queue files older than one hour. It probes Node before starting an engine and never starts another while port 31999 is listening. Its password is stored only in a current-user DPAPI file under `.local/`. Preview, nesting validation, DXF extraction/offset, PDF and CNC/DXF generation use this bridge when it is running. The site remains accessible while it is off, but those calculations are unavailable. Independent 24/7 hosting requires a supervised engine on a suitable server.

The standalone DXF parser reads modelspace, converts supported entities to flattened paths, joins open edges into closed loops within a configurable tolerance, and emits JSON in millimetres. It treats unitless DXF as millimetres and rejects unsupported units/open contours.

Each part upload stores the DXF on Laravel's private local disk and queues `ExtrairGeometriaDxf`. That job invokes Python with a Symfony Process argument array, saves raw contours and bounding dimensions, or saves an error status. A batch JSON endpoint gives the parts list its polling data.

Kerf compensation is a separate Python operation. The order-specific input uses `offset_mm = +kerf_mm / 2` to move external laser centerlines outward from the nominal DXF edge; hole contours receive the opposite offset inside the same Python operation. Raw part geometry is never overwritten. The CNC program reuses compensated geometry saved with the nesting result. The sign was confirmed against the supplied manual CNC: a 251.5 × 130 mm DXF rectangle becomes a 253.5 × 132 mm external cut at 2 mm kerf.

The Node engine generates no-fit-polygon contact candidates with a Minkowski sum, sampling detailed outlines for search speed and retaining bounding-box fallbacks. It searches order/rotation genes until its generation or time limit. Polygon clipping and cut-contour distance validate potentially overlapping placements; disjoint bounding boxes and rectangular-sheet bounds are checked directly. It returns a partial result with unplaced IDs when necessary. Coordinates are lower-left translation after rotating and normalizing the part's bounding box.

Automatic placement ranks contact candidates by increasing X, then Y, filling the left edge vertically before advancing right. Complete layouts are scored primarily by the occupied horizontal extent, with vertical extent as a tie-breaker; placed count and geometric area retain their higher priorities. The conservative reusable rectangle is still selected from the free top and right strips by area, so the layout objective usually leaves a full-height remnant on the right of a wide sheet.

For detailed contours on rectangular sheets, the Node endpoint first obtains a conservative complete/partial layout, then launches a time-bounded Python quality search. The Python side sorts DXF rings by area before treating inner rings as holes, matching Node normalization regardless of DXF entity order. Pyclipper proposes contacts from up to 32 sampled outer vertices per rotation; a cached horizontal slide of complete polygons adds same-row contacts missed by sparse Minkowski vertices. Shapely tests the full compensated polygons, including holes and the material-thickness thermal clearance, before each placement. For repeated batches with rectangular, broad and slender profile groups, a bounded pattern search tries staggered rows, an edge strip and alternating two-column packing with a few reserved profiles for pockets. These are derived from current sheet and part dimensions, not imported CNC coordinates. Other shapes retain the ordinary order/rotation search. The search compacts complete ordinary candidates left/down, then tries relocating protruding pieces. Node independently validates every returned candidate and retains its own result if Python is unavailable or invalid.
Multi-contour batches and simple oblique outlines enter the Python search, even when no ring exceeds 48 vertices (including one oblique part). `search_nesting.py` allocates 30% of a 45-second budget to the legacy pattern/compaction engine, 65% of the remainder to `compact_nesting.py` for feasible-region nesting/group repacking, then the remaining time to `angular_nesting.py`. The angular phase derives orientations from long edges and neighbours, tests coarse turns and fractional adjustments, and periodically removes/reinserts neighbouring pieces. RegionPacker generates orientations lazily, preserves fractional incumbents and export angles, and bounds its NFP cache to 4,096 entries. Pyclipper subtracts the union of no-fit obstacles from the translation region, including joint-contact intersections. Large-first constructions alternate with local removal/reinsertion and perturbed restarts; small fillers prefer actual interior feasible regions obtained from the inner Minkowski sweep. External search simplifies by 0.15 mm, internal fitting by 0.025 mm, with corresponding candidate inflation and exact Shapely validation of full contours. The saved layout is reindexed by the current grouped piece order in `MotorNesting` and passed as an incumbent; Python reconstructs its shapes and validates instances, bounds and gaps before using it. Complete candidates compete by the largest intact top/right remnant, with neutral compacting moves supporting further search. Node independently validates the proposal and retains its baseline on failure. Total HTTP processing remains bounded under Laravel's 60-second limit; this heuristic portfolio does not claim global optimality.

The detailed search also receives simple orthogonal outlines with reentrancies and four-corner parts that cannot fit the usable sheet at cardinal angles but could fit obliquely. When the incumbent is incomplete, angular construction tries large-first, longest-first and small-first orders in both top-remnant and right-remnant directions. Parts that cannot fit at cardinal angles receive 15-degree initial orientation seeds before fractional refinement. Exact clearance and the incumbent quality floor still govern acceptance.
Single-piece detailed searches go straight to a two-second angular budget, avoiding a full batch-search delay for a simple diagonal fit.

`RodarNesting` is the order orchestration job. It reads the selected sheet's kerf, calls Python offset per part, sends compensated contours to the Node engine, rejects incomplete placements, persists the engine result including compensated contours, and calculates cutting time through `CalculadoraTempoCorte`. Orders with failures enter an explicit error state. HTTP details and status polling remain in Laravel.

The Konva editor reads sheet, compensated outlines and CNC toolpaths from either a temporary optimization preview or a saved order. Its positions use the same rotate-then-normalize-then-translate contract as the engine. Laravel validates all submitted instances and sheet containment; Node's `/avaliar` endpoint rejects overlap, recomputes utilization and a conservative remnant. The preview places the canvas before metrics so pieces packed at the sheet's lower edge remain visible in the initial viewport. Drag and rotation update the canvas continuously and save preview positions on release; navigation waits for any pending save. Operators can also reorganize automatically or edit a ready exported order and regenerate its CNC. Thin screen-space cut strokes and zoom/pan controls allow operators to inspect clearances that are smaller than a pixel in full-sheet view; the view transform does not change saved positions or CNC.

The saved-order editor can request automatic reorganization without writing to inventory. It maps the engine's batch instance numbers back to the order's existing instance IDs, validates all positions and CNC lead paths, and applies the proposal to the browser canvas. A strictly larger reusable remnant is required for ordinary reorganization, but an increased material clearance may reduce the remnant. Confirmation uses the existing transactional edit path to update the order, remnant, costs and CNC. The PDF download runs on demand through Symfony Process and ReportLab, reading the current saved compensated contours and the same rotation/translation contract as the CNC; no stale PDF copy is stored. Its A3 sheet report groups quantities by piece code, shows nominal material area and gross scrap from original DXF contours, draws saved compensated cut contours, and reports reusable rectangular remnant separately. Optional density on `materiais` converts nominal area and thickness to estimated piece/sheet mass; it is not a machine calibration.

On batch export, one ready order represents the complete batch. Its legacy sheet/result fields hold sheet 1, while `pedido_chapas` holds sheets 2 onward; all pivot quantities and order totals cover the complete batch. `EstoqueDoArranjo` locks and decrements each physical sheet once, records a movement linked to the common order, and registers each reusable rectangular remnant. Zero-balance used sheets remain as historical `Baixada` records. `ProgramaCnc` plans lead-ins/outs and holes-before-externals for each sheet; `GerarCncSaida` writes a separate private CNC and technical DXF per sheet. The order detail provides each download, PDF and visual editor, and deletion transactionally reverses all sheets and unused remnants together. Changes to an exported sheet update its remnant and the common order totals. Production start and completion apply to the whole order without a second stock debit. Legacy single-sheet orders retain the original fields and behavior.

Orders can be deleted before production starts. A transactional deletion of an exported order locks its sheet and remnant, returns one sheet unit to available stock, withdraws its unused remnant, and records reversal movements plus an audit event. Deletion is blocked while nesting runs, after production starts, or when the remnant has another consumer or child. Historical sheet/remnant records and movements remain for traceability; private CNC/DXF outputs are removed after commit.

Each sheet carries a unit cost; each material thickness carries an hourly machine rate. Exported order material cost is the used sheet cost less the proportional value assigned to the reusable remnant. Machine cost is hourly rate times estimated cutting seconds, replaced by actual seconds when supplied. The order list filters by status and creation dates; the detail page separates order composition/downloads, management and cost into three client-side tabs. The management tab controls forecast/delivery dates, actual time and production state. The part catalog list shows its operator-facing name, DXF format and dimensions without exposing internal storage filenames or processing state.

Order completion stores a dedicated `concluido_em` timestamp. Exact sheet and compensated-piece areas are persisted when nesting finishes (and backfilled for older results), allowing filtered report averages and totals to run as SQL aggregates. The dashboard also uses grouped SQL counts/sums. Native Laravel Gates protect administration; an active-user middleware blocks deactivated accounts. Eloquent observers record critical status and stock events in `historico_acoes`, within the same database transaction as the source change.

## Otimizar

Ready, exported orders can be revised before production. The edit screen starts with every current catalog piece and its quantity; the operator may change quantities, remove rows, or use a modal to upload DXFs or search for more catalog pieces. It sends the complete desired catalog list with `substituir_pecas=1`, so omitted rows are removed instead of silently added back. Older add-only clients without that flag retain additive behavior. The preview replans the entire requested batch using already-reserved physical sheets first and other compatible free stock for overflow. The old generated remnants are excluded from candidate stock. Material and thickness stay tied to the reserved sheets; the form exposes kerf, safe margin, lead-in and tabs, and derives thermal clearance from the thickness profile. Confirmation locks and verifies the order fingerprint, thickness, part versions and source-sheet stock, then reverses the old debits, replaces the arrangements and pivot quantities within the same order, debits the newly assigned sheets and regenerates per-sheet CNC/DXF outputs. Used remnants or a production status block the transaction. The PDF is generated on demand from the revised saved layout.

The authenticated batch flow accepts up to 20 private DXFs plus any number of processed catalog parts, with per-part quantities and a combined 100-instance total limit inherited from the nesting engine. The initial form does not load the catalog; a bounded authenticated search by name or ID returns up to ten processed pieces per query, and only added pieces become form inputs. `GeometriaDxf` and `MotorNesting` are shared with the queued order workflow: extraction and kerf compensation happen once, while automatic reorganization on another compatible sheet reuses cached contours and calls only the nesting engine. Planning processes compatible physical sheet slots in sequence, prioritizing remnants before new sheets and respecting each `chapa.quantidade_disponivel` after subtracting only active orders whose stock has not yet been debited. Positioned instance counts are subtracted from the remaining quantities before the next sheet. The preview and ownership are held in the database cache for 15 minutes; uploaded files remain in `storage/app/private/previews/<token>/`, and a scheduled command removes inactive directories after 20 minutes. The interactive preview canvas uses the editor's Konva rendering contract and shows each sheet, utilization, estimated batch time, positioned count and unplaced pieces.

The preview stores an optional kerf override and a numeric sheet-edge margin. Each material thickness supplies mandatory `espacamento_minimo_mm` strictly above kerf and `lead_in_mm`; the effective edge margin is at least the thermal spacing. Thermal clearance is measured between actual compensated cut contours, including concavities; irregular remnants also check the real outline rather than only a bounding rectangle. A settings change reapplies offset from each original contour and replans every sheet. Python checks corner/reentrant pierce and lead-in paths against the safe area and other material. The settings travel with the nesting result into the order so later editor validation and CNC/DXF regeneration use the same limits. The Konva editor overlays a dashed safe-area border, planned paths and tabs, visual code/cut-order labels, a session-local 50-step undo/redo history for positions, rotations and order, and utilization next to estimated time. When lead planning fails, geometry remains visible with a diagnostic while export remains blocked until corrected.

Preview creation and sheet retries do not write pieces or orders. Export requires all requested instances to be allocated, rechecks sheet stock and versions plus thickness and catalog part versions, and creates processed piece records for new DXFs plus one ready order for the batch in one database transaction. Existing catalog parts are reused. The order's pivot quantities equal all instances across its sheets. Original uploaded DXFs are copied once to permanent private storage; cached geometry/placements become each sheet's result. The preview is then removed. Files copied during a failed transaction are deleted; a cache lock prevents duplicate export.

## Physical cutting profile (2026-09-27)

`espessuras_material` stores thermal spacing and lead-in length separately from kerf. The configuration form permits a profile clearance strictly greater than kerf; most profiles remain at 10 mm, while the A36 19.05 mm manual-CNC benchmark profile uses 2.1 mm by explicit user request. `pedidos_corte` stores the optional tab switch and tab length. `RodarNesting` uses the profile clearance for both piece spacing and sheet-edge margin. Batch previews initialize both values from the profile but let the operator increase them independently for one arrangement; the controller rejects values below the profile minimum and a piece spacing at or below kerf. Node validates exact cut-path distances and the actual edge of irregular remnants. Remnant outlines and their stored width/height share the same 0.001 mm coordinate precision so the engine does not reject a contour that exceeds a rounded dimension by a fraction of a micron. Previous orders retain their stored result and CNC until explicitly edited; editing reapplies the current thickness minimum, validates the full layout, and only then regenerates outputs.

The Python CNC planner and technical DXF generator share one path plan. It picks a clear corner or reentrant pierce and lead-in, then orders validated contours by containment depth (deepest first). A piece nested in a cutout is finished before that host cutout is released; its own holes precede its exterior. At equal depth, holes precede small-to-large exterior releases. There are no independent skeleton cuts to schedule. Optional tabs are open gaps in external cuts, represented in the DXF `TABS` layer and in the canvas; the CNC omits those segments. `CalculadoraTempoCorte` uses the same containment ordering, lead distance and tab-adjusted cut length for its estimate. `GerarCncSaida` generates both private outputs from the confirmed result; CNC remains the controller file and DXF is a technical review file. Changing tabs on a ready order validates the plan, recalculates time/cost and regenerates both outputs.

Canvas labels use explicit contrasting screen-space styles independent of the dark app shell. At full-sheet scale, labels that cannot fit or would overlap are hidden; hovering a part reveals its code and index. Zoom/pan recalculates label visibility without changing geometry or machine output.
